## 2026-10-21 Hover 运动过程补修

上一轮静态终态检查没有覆盖眼球和相关项目卡片的布局投影，也不能证明整个 Hover 运动曲线一致。本轮按原版发布模块补修：

- `src/scripts/hover.js` 统一管理共享组件；刚度 500、阻尼 60、质量 1、延迟 0。布局按 0→1000、复杂属性按 0→100 运行，各自使用原版收尾条件；不再用一个固定 0.7 秒 CSS 过渡。
- 眼球平移 6px；项目图、间距、内边距及文字位置通过布局投影变化，子层抵消父层缩放，保持文字和圆角的形态。中途移开从当前视觉位置重新投影，不跳回起点。
- 颜色按原版平方 RGB 通道混合，透明度线性混合。社交图标的直接换色保持原组件行为。菜单项、手机作品卡片及手机相关卡片原本无 Hover 动画，继续保持静态。
- 相关项目图片放大时，响应式尺寸声明从 360px／280px 切换到 400px／320px，移开后恢复。
- 独立 RK4 数值积分核对 2,002 个时间样本；浏览器测试覆盖 5 页 × 3 尺寸、78 个组件实例的进入、移出及 80ms 中途反向；全部复位无残留变形。手机展开菜单的眼睛额外实测，键盘 Tab 聚焦 Resume 的 Hover 状态通过。

浏览器测试中约 60 万次几何字段采样是本地实现与原版数学模型的比较，不是两个网站同步逐帧录像。原站逐帧读取有较大工具延迟，未取得同步录像。原站与修复版的眼睛端点、桌面相关卡片尺寸和圆角另行进行了浏览器核对。完整范围和数值保存在 `hover-audit.json`；可重复的公式回归检查为 `node scripts/check-hover.mjs`。
